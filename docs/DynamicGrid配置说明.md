# DynamicGridStrategy 配置文件详细说明

## 📖 概述

`copy_config.json` 是 DynamicGridStrategy 动态网格策略的核心配置文件，定义了多币种网格交易的所有参数。该配置文件采用 JSON 格式，支持热更新，可以在不重启系统的情况下动态调整策略参数。

## 🏗 配置文件结构

配置文件主要包含两个顶级部分：
- **pairs**：交易对配置数组，定义每个币种的网格参数
- **signals**：技术指标信号配置，控制开仓时机

## 🎯 交易对配置详解 (pairs)

### 基础设置

#### pair
- **类型**：字符串
- **说明**：交易对名称，格式为 `基础币/计价币:保证金币`
- **示例**：`"BTC/USDT"`（现货）或 `"BTC/USDT:USDT"`（期货）
- **注意**：必须与交易所支持的交易对格式一致

#### is_short
- **类型**：布尔值
- **说明**：网格方向控制
  - `false`：多头网格（低买高卖）
  - `true`：空头网格（高卖低买）
- **示例**：BTC设为 `false`（看多），ETH设为 `true`（看空）
- **应用场景**：可同时部署多空网格实现对冲

#### enabled
- **类型**：布尔值
- **说明**：该交易对是否启用
- **用途**：临时禁用某个交易对而不删除配置

### 网格层级设置

#### n_levels
- **类型**：整数
- **说明**：网格层级数量，决定最大同时持仓层数
- **示例**：`10`（支持最多10层同时持仓）
- **建议**：
  - 新手：3-5层
  - 进阶：5-8层  
  - 专业：8-15层

#### amount
- **类型**：浮点数数组
- **说明**：每层的投资金额（单位由 amount_mode 决定）
- **长度**：必须等于 n_levels
- **示例**：`[10000.0, 10000.0, ...]`（每层1万USDT）
- **配置建议**：
  - 均匀分配：每层相同金额
  - 金字塔式：越深层级金额越大
  - 倒金字塔：越浅层级金额越大

### 网格比例参数

#### op_ratios（开仓比例）
- **类型**：浮点数数组
- **说明**：相对于前一层开仓价格的偏移比例
- **计算公式**：
  - 多头：`当前层开仓价 = 前一层开仓价 × (1 - op_ratio)`
  - 空头：`当前层开仓价 = 前一层开仓价 × (1 + op_ratio)`
- **示例**：`0.01` 表示1%的价格间距
- **配置策略**：
  - 均匀间距：所有层使用相同比例
  - 变化间距：根据层级调整间距大小

#### tp_ratios（止盈比例）
- **类型**：浮点数数组
- **说明**：每层的止盈目标比例
- **计算公式**：
  - 多头：`止盈价 = 开仓价 × (1 + tp_ratio)`
  - 空头：`止盈价 = 开仓价 × (1 - tp_ratio)`
- **示例**：`0.01` 表示1%止盈目标
- **配置建议**：
  - 保守：0.5-1%
  - 平衡：1-2%
  - 激进：2-5%

### 智能回调参数

#### op_rebound_ratios（开仓回调比例）
- **类型**：浮点数数组
- **说明**：开仓前等待的价格回调比例，避免追高杀跌
- **工作原理**：
  - 价格触发开仓条件后，等待价格回调确认
  - 多头：等待价格从最低点反弹指定比例
  - 空头：等待价格从最高点回落指定比例
- **示例**：`0.0015` 表示等待0.15%的回调确认
- **配置建议**：
  - 高波动币种：0.2-0.5%
  - 中波动币种：0.1-0.2%
  - 低波动币种：0.05-0.1%

#### tp_rebound_ratios（止盈回调比例）
- **类型**：浮点数数组
- **说明**：止盈激活后等待的回调比例，实现追踪止盈
- **工作原理**：
  - 价格达到止盈目标后激活追踪
  - 等待价格从极值点回调指定比例后执行止盈
- **示例**：`0.001` 表示等待0.1%的回调确认
- **优势**：最大化捕获价格波动，避免过早止盈

### 全局风险管理

#### 价格比例止盈
```json
"enable_global_tp_price_ratio_check": true,
"global_tp_price_ratio": 0.02
```
- **说明**：基于平均持仓成本的价格比例止盈
- **触发条件**：当前价格相对平均成本的收益率达到设定比例
- **示例**：2%表示整体收益率达到2%时全局止盈

#### 金额止盈止损
```json
"enable_global_tp_amount_check": true,
"global_tp_amount_target": 10000.0,
"enable_global_sl_amount_check": true,
"global_sl_amount_target": 20000.0
```
- **说明**：基于绝对金额的全局风控
- **tp_amount_target**：盈利达到目标金额时全局止盈
- **sl_amount_target**：亏损达到目标金额时全局止损

### 高级设置

#### amount_mode
- **类型**：字符串
- **可选值**：`"quote"`（计价币）或 `"base"`（基础币）
- **说明**：amount 数组的单位模式
- **示例**：
  - `"quote"`：amount 表示 USDT 金额
  - `"base"`：amount 表示 BTC 数量

#### skip_first_level_rebound
- **类型**：布尔值
- **说明**：是否跳过第0层的激活等待
- **用途**：
  - `true`：第0层收到信号后直接开仓
  - `false`：第0层也需要等待价格回调确认

#### skip_levels_exit_number
- **类型**：整数
- **说明**：前N层禁用内部止盈，只允许全局止盈
- **示例**：`0` 表示所有层都启用内部止盈
- **用途**：避免浅层过早止盈，让深层有机会平仓

## 📊 技术指标配置详解 (signals)

### CCI 指标配置
```json
"cci": {
  "use_signal": false,
  "timeframe": "15m",
  "cci_length": 20,
  "cci_long_threshold": -100,
  "cci_short_threshold": 100
}
```

#### 参数说明
- **use_signal**：是否启用CCI信号
- **timeframe**：CCI计算的时间框架
- **cci_length**：CCI计算周期
- **cci_long_threshold**：多头开仓阈值（通常为负值）
- **cci_short_threshold**：空头开仓阈值（通常为正值）

#### 配置建议
- **时间框架**：5m-1h，较高框架信号更可靠
- **长度**：14-20，越短越敏感
- **阈值**：±100是经典设置，可调整为±80或±120

### RSI 指标配置
```json
"rsi": {
  "use_signal": true,
  "timeframe": "1m",
  "rsi_length": 14,
  "rsi_long_threshold": 50,
  "rsi_short_threshold": 50
}
```

#### 参数说明
- **use_signal**：是否启用RSI信号
- **timeframe**：RSI计算的时间框架
- **rsi_length**：RSI计算周期
- **rsi_long_threshold**：多头开仓阈值
- **rsi_short_threshold**：空头开仓阈值

#### 配置建议
- **经典设置**：长阈值30，短阈值70
- **敏感设置**：长阈值40，短阈值60
- **中性设置**：长短阈值都设为50（示例配置）

## 🎛 配置策略与技巧

### 1. 新手入门配置
```json
{
  "n_levels": 3,
  "amount": [5000, 5000, 5000],
  "op_ratios": [0.02, 0.02, 0.02],
  "tp_ratios": [0.02, 0.02, 0.02],
  "op_rebound_ratios": [0.002, 0.002, 0.002],
  "tp_rebound_ratios": [0.001, 0.001, 0.001]
}
```
- 层数少，风险可控
- 间距大，不易被套
- 回调设置保守

### 2. 进阶用户配置
```json
{
  "n_levels": 6,
  "amount": [8000, 8000, 10000, 10000, 12000, 12000],
  "op_ratios": [0.015, 0.015, 0.02, 0.02, 0.025, 0.025],
  "tp_ratios": [0.015, 0.015, 0.02, 0.02, 0.025, 0.025],
  "op_rebound_ratios": [0.0015, 0.0015, 0.002, 0.002, 0.0025, 0.0025],
  "tp_rebound_ratios": [0.001, 0.001, 0.0015, 0.0015, 0.002, 0.002]
}
```
- 金字塔式加仓
- 变化间距适应波动
- 精细化回调设置

### 3. 专业交易者配置
```json
{
  "n_levels": 10,
  "amount": [动态配置],
  "op_ratios": [梯度间距],
  "tp_ratios": [自适应止盈],
  "op_rebound_ratios": [智能回调],
  "tp_rebound_ratios": [追踪止盈]
}
```
- 高层数深度网格
- 动态参数优化
- 复杂风控策略

## ⚠️ 配置注意事项

### 1. 数组长度一致性
- 所有比例数组长度必须等于 n_levels
- 系统会在启动时验证配置完整性

### 2. 参数合理性检查
- op_ratios：建议0.5%-5%范围
- tp_ratios：建议0.5%-10%范围
- rebound_ratios：建议0.05%-1%范围

### 3. 资金安全
- 合理设置全局止损，控制最大损失
- 避免单一币种投入过多资金
- 建议总投入资金不超过账户的70%

### 4. 市场适应性
- 高波动币种使用较大间距
- 低波动币种使用较小间距
- 根据市场环境及时调整参数

## 🔧 配置文件管理

### 热更新操作
1. 修改配置文件
2. 通过UI界面点击"重新加载配置"
3. 或发送POST请求到 `/dynamicgrid/reload`

### 备份与恢复
- 建议在重大修改前备份配置文件
- 可以为不同市场环境准备多套配置
- 使用版本控制管理配置变更

### 配置验证
- 系统启动时自动验证配置格式
- 参数超出合理范围时会发出警告
- 建议在测试环境先验证配置

## 📈 配置优化建议

### 根据币种特性调整
- **BTC**：较大间距，保守设置
- **主流币**：中等间距，平衡设置
- **小币种**：灵活间距，谨慎设置

### 根据市场环境调整
- **牛市**：减少层数，扩大间距
- **熊市**：增加层数，缩小间距
- **震荡市**：优化回调参数

### 定期回测优化
- 分析历史表现数据
- 调整不合理的参数设置
- 根据市场变化持续优化

---

**重要提醒**：配置参数直接影响策略表现和风险水平，建议在充分理解各参数作用的基础上谨慎调整，并在小资金环境下充分测试后再应用到正式交易中。
